### 0.2 前提勘误

任务前提"刀目前没有皮肤槽"**与代码现状不符**：刀皮的数据层（F3/F4/F5）与 UI 层（F6）基建均已存在。本规格的真实工作面收敛为三件事：

1. **槽位常态化**：将刀具涂装从枪皮页内的一个页签，明确为与 `GUN_CN` 8 类枪**并列的近战类（melee）皮肤槽**（§1）；
2. **首版内容定稿**：从 F4 已有 6 种涂装中选型、定土豆世界观命名与视觉描述（§2）；
3. **获取途径双轨**：现状获取 = 300 币购买 + 三连解锁；本规格新增**搜打撤稀有掉落**通道，形成"黑市商店（保底）+ 搜打撤掉落（博上限）"双轨（§4）。

美术资源**零新增**即可落地（§3），符合"不引入新文件类型"红线。

## 3. 贴图实现建议

| 方案 | 结论 |
| --- | --- |
| **A. tiles.webp 图集复用（推荐，首版采用）** | F4 已确认 5 款对应的全部 tile 索引（含 0~15 帧动画序列与 glow 变体）存在于现有图集，注册表（data.js tile id 段 939~972 区间同构）已就绪。**零新增资源、零扩格、零新文件类型**，美术工作量仅为命名与商店/掉落文案。规格的"美术资源在现有机制内落地"红线由此满足 |
| B. tiles.webp 图集扩格 | 仅当后续新增**原创**刀皮（图集内无对应变体）时使用：在图集尾部按既有 tile 规格开新格（对齐 `tw:128,th:32`、`res:128` 惯例），data.js 注册新 tile id。流程与枪皮新增涂装一致，不引入独立贴图文件 |
| C. 独立贴图文件 | **否决**：违反红线；且会破坏图集 single-draw 的批量渲染路径（bbmodel texs 机制按图集索引寻址） |

实现注意：涂装应用走 F5 现有 `kn.paint` → `melee[key].paints[paintKey]` tile 映射 → `knifeStack()` 产出 `{id, xz:{paint}}` 引用链，**不复制贴图数据、不新建纹理对象**。

### 4.3 经济自洽校验

- 双轨不冲击 03 号文档经济：涂装 300 币 = 现有 `PAINT_PRICE` 不变；搜打撤凭证是**概率免费通道**，保底价仍为 300 币，符合"经济无硬门槛"红线（白板玩家进图也有机会搏到涂装）。
- 单局期望掉落价值远低于 500 币变现封顶（凭证不可变现，仅重复折算 50 币），无通胀入口。

## 5. 验收标准（共 5 条）

1. **槽位**：皮肤页出现与 8 类枪并列的近战类槽位；匕首、折叠刀两把刀均可进入涂装选择；默认态（无涂装）显示与现状一致。
2. **内容与贴图**：5 款刀皮按 §2 清单上线，展示名与 paint key 映射一致；涂装后第一/第三人称手持模型、击杀播报图标（`g3Icon`）贴图同步正确；资源审计确认全部来自 tiles.webp 既有索引，**无新增贴图文件、无图集扩格**（首版）。
3. **双轨获取**：黑市 300 币购买 5 款任一可用（扣币、入 `kp`、可装备）；搜打撤 T3/T4 容器/AI 掉落可产出两类凭证，撤离成功后仓库页可兑换对应档位涂装（三选一/二选一），死亡局凭证丢失。
4. **防刷与红线**：凭证不可变现（变现清单与 `sellValue` 均为 0）、不可交易；重复集齐后折算 50 币路径正确；刀皮涂装不改变任何战斗数值（伤害/攻速/范围代码走查 + 实测对照）。
5. **存档与数值**：`kown`/`kp`/`kn` 状态随现有账号存档/cloudsave 域同步，换设备不丢；掉落权重与折算币值集中于调参块，无散落硬编码。
