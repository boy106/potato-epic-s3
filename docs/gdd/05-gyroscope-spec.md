## 0. 已拍板决策（用户定稿，本文档不可推翻）

1. **档位三档**：关闭 / 开镜开启 / 总是开启，默认「开镜开启」。

## 1. 设置项定义表

### 1.1 存储策略结论

新功能无旧数据，**首版直接新增 key，不做迁移**。命名对齐现有触控设置的存储习惯：

- 若现有设置是**单对象序列化**（如 touch 设置整体存一个 key），则在该对象上**新增三个字段**（推荐，一次读写、与触控设置同生命周期）；
- 若现有设置是**独立 key 平铺**，则新增以下 key（前缀 `pe_` 为建议前缀，实现时以源码树还原后的实际前缀惯例为准，保持一致即可）：

| 设置项 | 建议 key | 类型 | 取值域 | 默认值 |
| --- | --- | --- | --- | --- |
| 陀螺仪档位 | `pe_gyro_mode` | int 枚举 | `0` 关闭 / `1` 开镜开启 / `2` 总是开启 | `1`（开镜开启） |
| 基础灵敏度 | `pe_gyro_sens_base` | int | 10–300（步进 5，单位 %） | `100` |
| 开镜灵敏度 | `pe_gyro_sens_ads` | int | 10–300（步进 5，单位 %） | `100` |

> 若并入单对象：字段名 `gyroMode` / `gyroSensBase` / `gyroSensAds`，取值域同上。

### 1.2 生效时机

| 场景 | 生效行为 |
| --- | --- |
| 主菜单设置页改动 | **立即写入存储并生效**（下次进入对局按新值运行） |
| 靶场对局内 | **允许实时调整并即时生效**（★ 倾向性结论，理由见 §6.3） |
| 对战类对局中（1V1/2V2/淘汰赛/乱斗） | 设置项锁定不可改（见 §6.2） |
| 首次选择非「关闭」档（iOS 13+） | 需先通过权限流程（§3），授权后才写入档位 |

### 1.3 语义约定（实现侧必须遵守）

- `pe_gyro_mode = 0` 时，两个灵敏度滑条**仍显示但置灰**（保留用户已调数值，切回非关闭档不丢配置）。
- 灵敏度值为**百分比增益**，含义见 §5.1；`100` = 基准增益，不是"最高"。
- 三个 key 互相独立读写；删除任一 key 不影响其他两个（读取到缺失/非法值时按默认值处理，不报错）。

## 2. 设置页布局

### 2.1 分组与位置

- 放入**移动端高频设置组**，与现有「开镜模式」「灵敏度（触屏）」「准星设置」同组或紧邻成组，**分组标题「陀螺仪」**。
- 不复刻竞品"枪械及陀螺仪（服务器同步）"标题——本项目首版不做服务器同步，标题不得出现"服务器同步"字样，避免误导。
- 竞品同页的"探头按钮转动视角"等体感替代操作**不引入**（本项目无探头系统），后续如做再另立条目。

### 2.2 控件形态

| 控件 | 形态 | 说明 |
| --- | --- | --- |
| 陀螺仪档位 | 三档分段按钮（Segmented） | 「关闭 / 开镜开启 / 总是开启」，单选，默认高亮「开镜开启」 |
| 基础灵敏度 | 滑条 | 10–300，步进 5，显示当前数值（如 `100%`）；档位=关闭时置灰 |
| 开镜灵敏度 | 滑条 | 同上，独立取值 |
| 辅助说明文案 | 一行小字 | 「开镜开启：仅开镜时生效；总是开启：全程生效（需设备支持）」 |

- 两个滑条仅在档位 ≠ 关闭时可用；档位切回「关闭」滑条置灰但**不重置数值**。
- 分组内不出现"恢复默认"独立按钮，统一走设置页全局「恢复默认」。

### 2.3 桌面端 / 无传感器隐藏规则

满足任一条件则**整组隐藏**（连标题一起）：

1. 非 touch 环境（无 touch 事件能力 / 桌面 UA 判定，复用现有移动端判断入口）；
2. `window.DeviceOrientationEvent === undefined` 且无 `DeviceMotionEvent` 降级路径；
3. 检测 1.5s 内 `deviceorientation` 从未触发过有效数据（β/γ 全为 null）——此项仅用于"设置了却静默失效"的兜底，见 §7.2。

### 2.4 「恢复默认」行为

- 全局「恢复默认」将三项重置为默认值：档位=开镜开启、双滑条=100%。
- **★ 权限前置约束**：若设备此前拒绝过陀螺仪权限（或从未授权），恢复默认时档位写入 **`0`（关闭）** 而非默认值 `1`，并弹一次 toast：「陀螺仪需要授权后才能开启」。避免出现"界面显示开着、实际不生效"的死状态。
- 恢复默认**不触发权限请求弹窗**（权限请求只允许由用户主动点选非关闭档触发，见 §3）。

> **实现注记（主理人裁定，2026-11-21）**：W5b 实现时发现还原源码树中不存在全局「恢复默认」按钮（原版设置页无此控件），故入口落于陀螺仪分组内。**裁定接受此偏差**：行为完全符合上述约束（含未授权写 0 + toast），仅入口位置不同；若日后原版补全局恢复默认按钮，陀螺仪三项应并入其重置范围。

## 3. 权限请求流程（iOS 13+）

### 3.1 触发条件

- 仅当存在 `DeviceOrientationEvent.requestPermission`（iOS 13+ Safari / webview）时走本流程。
- **必须在用户手势的当次点击回调内同步调用 `requestPermission()`**——不得延迟、不得放进 promise 链、不得在页面加载时预请求。
- Android 及无权限 API 环境：跳过本节，选档即生效。

### 3.2 流程

```
用户点击「开镜开启」或「总是开启」
        │
        ├─ 已授权（之前 granted）？ ── 是 → 直接切换档位，生效
        │
        └─ 否 → 当次点击回调内调用 requestPermission('deviceorientation')
                 │
                 ├─ granted ──→ 写入档位，生效，无需 toast
                 │
                 ├─ denied ──→ 档位回退为「关闭」（UI 分段按钮同步回弹）
                 │             弹一次性 toast（文案见 3.3）
                 │
                 └─ 抛异常 / 返回非 granted 字符串 ──→ 按 denied 处理（同上）
```

- 请求期间分段按钮**不显示中间态**（点击后按钮不先切过去再弹权限；授权结果落地后再更新 UI）。
- 同一会话内用户反复点击重试：**每次都重新发起请求**（iOS 允许重复请求，系统可能直接返回上次结果）；但 **denied toast 每会话最多弹 2 次**，第 3 次起静默回退，防止骚扰。

### 3.3 Toast 文案（定稿）

- 权限被拒绝：「未获得陀螺仪权限，陀螺仪已关闭。可在系统设置中允许后重试。」
- 系统/环境异常（请求抛错）：「当前环境不支持陀螺仪，已关闭。」

### 3.4 权限 API 存在但被系统级关闭（iOS「设置 → Safari → 动作」或全家桶运动与健身权限关闭）

- `requestPermission` 会直接返回 denied，走 §3.2 denied 分支，无独立处理路径。
- **不做**"跳转系统设置"引导按钮（Toy webview 无法保证能拉起对应设置页，首版不引入不可控跳转）。

## 4. 状态机

### 4.1 状态定义

```
陀螺仪有效状态 = f(档位, 开镜标志, 对局状态, 输入仲裁, 可见性)

有效 = (档位==2 && 对局活跃 && 存活 && 页面可见 && 无更高优先级视角输入)
    || (档位==1 && 开镜标志 && 对局活跃 && 存活 && 页面可见 && 无更高优先级视角输入)
```

输出只有两态：**激活 / 挂起**。不存在"半激活"。

### 4.2 「开镜开启」档的判定来源（钩子点描述，实现侧接入，不预设函数名）

实现侧需提供/暴露以下接入点（W5b 对齐用）：

| # | 钩子点 | 要求 |
| --- | --- | --- |
| H1 | **开镜状态标志位**（ADS 状态） | 需覆盖两种现有开镜模式（点击切换 / 长按）：开镜进入置 true、收镜置 false。若现成标志不存在，由实现侧补一个唯一事实源（single source of truth），**禁止**陀螺仪模块自行用"FOV 是否变化"推断开镜 |
| H2 | **视角 yaw/pitch 写入口** | 陀螺仪增量必须走与触屏滑动视角**相同的视角写入口**（同一入口天然实现帧级仲裁，见 §7.5），不得旁路直改相机 |
| H3 | **对局状态查询** | 能回答：是否在对局中 / 是否存活 / 是否观战 / 是否暂停或切后台 |
| H4 | **设置读写** | 三个 key 的读写入口 |
| H5 | **开镜灵敏度切换点** | 开镜瞬间读 `pe_gyro_sens_ads`，收镜瞬间切回 `pe_gyro_sens_base`；切换只影响**后续帧**的增量系数，不重算历史缓冲 |

### 4.3 档位切换即时生效

- 设置页改档：下一个应用帧（rAF）即按新档位判定，无需重进对局。
- 档位 2 → 1 切换时若当前未开镜：立即挂起，无过渡。
- 1 → 2 切换时若已在对局且存活：立即激活。

### 4.4 收镜 / 关档时的视角平滑截止（禁止视角跳变）

- **收镜瞬间**：丢弃所有未应用的 pending 增量缓冲，立即停止施加增量。
- 由于采用增量式模型（§5.4），视角本身就是逐帧累加的，停止施加即静止——**不产生视角跳变、不做任何回弹/回正**。
- 可选打磨项（W5b 酌情）：停止后施加约 **80ms 的指数衰减尾**（每帧增量 × 衰减系数），消除"急刹车"手感。此为手感项，不作为验收硬指标。
- 开镜灵敏度切换点同理：切换帧只换系数，缓冲内的历史增量不重算，**杜绝视角二次跳动**。

### 4.5 暂停 / 切后台

| 事件 | 行为 |
| --- | --- |
| 对局暂停 / 页面 `visibilitychange → hidden` / 切后台 | 陀螺仪挂起 |
| 恢复可见 | 陀螺仪恢复前**丢弃恢复后前 2 个 `deviceorientation` 事件**（后台恢复首帧数据常带大跳变，直接应用会导致视角瞬移） |
| 对局结束回结算/主菜单 | 陀螺仪挂起（档位不变，进下一局自动恢复判定） |

### 4.6 死亡 / 观战

- 死亡瞬间至观战/复活期间：陀螺仪**挂起**。理由：死亡镜头、观战镜头的视角由系统/被观战者驱动，陀螺仪增量会打架且无操作意义。
- 复活（2V2）后自动恢复判定，无需任何用户操作。
- 档位 UI 不因此变化（设置页在对局中本就锁定，见 §6.2）。

## 5. 灵敏度模型

### 5.1 滑条取值域：**结论 = 百分比 10–300%，步进 5，默认 100%**

理由：

1. **心智直观**：基准定义为「设备转 1°，视角 yaw 转 1°」，100% = 1:1。玩家调 150% 就是"比基准快一半"，无需理解小数倍率。
2. **默认值落在刻度正中**（100），上下等距可调；若用 0.1x–3.0x，默认 1.0x 在滑条 1/3 处，视觉重心别扭。
3. **避免 0 值**：最低 10%——0% 会让"档位开着但完全不响应"与"坏了"混淆；彻底关闭的诉求由档位=关闭承担，职责分离。
4. 步进 5 共 59 档，精度足够（±5% ≈ 每 1° 设备转动差 0.05° 视角，手感不可分辨），且触屏滑条好停。

内部换算：`增益 = 滑条值 / 100`，作用于原始角增量（弧度换算后）。

### 5.2 轴向映射（移动端横屏）

游戏**强制横屏**（竖屏不可玩，见 §7.4），轴向映射固定一套：

| 设备轴 | 视角轴 | 映射比例 | 说明 |
| --- | --- | --- | --- |
| 设备绕竖直轴转动（横屏 yaw） | 视角 yaw（左右） | **全量（1:1 × 增益）** | 左右手横移手机 = 转身，主操作轴 |
| 设备前后俯仰（横屏 pitch） | 视角 pitch（上下） | **0.8 × 增益（★ 倾向性结论）** | 竖直方向视角本身有上下钳制，1:1 时抬/压枪易过冲顶到钳制边界；0.8 折中精准与幅度。实现为**单一可调常量**（集中一处定义，勿散落硬编码），供上线后按手感数据一轮调参 |

### 5.3 死区 / 微抖过滤：**首版固定值，不暴露 UI**

- **单事件死区**：单个 `deviceorientation` 事件的角增量 |Δ| < **0.05°** 时丢弃。依据：手持微颤典型幅值 0.01–0.05°/帧（60Hz），该阈值恰好滤除生理性手抖，且低于任何有意的缓慢瞄准速度（慢移约 0.2°/帧）。
- **累计死区**：被丢弃的小增量**累进缓冲**；累计 < 0.1° 不应用，累计 ≥ 0.1° 时一次性应用全部累计值。作用：避免死区边缘"卡一下才动"的顿挫，慢速瞄准依然平滑连续。
- 取值理由：固定常量、集中定义；上线后如出现"太钝/太抖"反馈，只调这两个常量，不动结构。

### 5.4 低通平滑

- 一阶指数滑动平均（EMA）：`输出 = α×本帧增量 + (1-α)×上帧输出`，**α = 0.5**（60Hz 下约等效 1–2 帧滞后 ≈ 17–33ms，低于人类感知阈值）。
- 目的：抑制采样噪声毛刺，而非掩盖手抖（手抖由 §5.3 死区承担）。
- 常量集中定义，与 §5.2 pitch 比例、§5.3 死区同处一个调参块。

### 5.5 翻转选项（Invert）：**首版不做**

理由：需求面窄（无用户声音指向它）、增加设置项认知负担、与"辅助瞄准/开镜模式"等高频项抢版面。架构上增量取负即可支持，未来加一个布尔开关成本低，预留即可。

### 5.6 性能约束（硬性）

- `deviceorientation` 回调内**只做增量累加进缓冲**（读角值→差分→累加），不做 EMA、不做死区、不碰视角。
- 缓冲在**游戏主循环 rAF 内**统一消费：死区 → EMA → 系数换算 → 经 H2 视角入口写入。
- 差分基准：保存上一事件角值；换算注意 60Hz 事件流的角度回绕与 ±180° 跳变处理。

## 6. 排位与公平性

### 6.1 已定事实

排位（1V1/2V2 天梯）**开放陀螺仪**；默认档「开镜开启」；首版本地存储不同步。此三条为用户定稿，本文档只补执行细则。

### 6.2 对局内锁定：**结论 = 强制锁定（除靶场）**

- **对战类对局进行中**（1V1 / 2V2 / 淘汰赛 / 乱斗，含死亡观战与暂停态）：设置页中陀螺仪整组**置灰锁定**，需退出对局回到主菜单设置页才能修改。
- **理由**：
  1. 对局中途开关陀螺仪可被用于非常规操作（如开枪瞬间切档规避手感干扰），有公平性观感风险，与"排位开放"的前提冲突；
  2. 对局内改档会触发权限流（iOS），弹窗打断对局体验；
  3. 与项目既有惯例对齐（见 6.3）。

### 6.3 与"黑市辅助页"惯例的对齐

黑市平板辅助页已有「无限弹药（**对局里不生效**）」的先例——本项目已确立"功能声明 + 对局内失效"的处理惯例。陀螺仪的处理**对齐该惯例但方向相反**：辅助页是"主菜单可用、对局失效"，陀螺仪是"主菜单可设置、对局中设置锁定、对局内按已设档位正常运行"。共同原则是：**凡影响对局操作的开关，其状态变更只能发生在对局外**。

### 6.4 靶场例外：**★ 倾向性结论 = 靶场内允许实时调整**

- 理由：灵敏度调参的主场景就是靶场（试手感→出设置→改数值→回来试的循环）；靶场无对抗性，锁定无公平收益，只有体验损失。
- 风险评估：靶场数据不进排位，无可利用面。
- 若测试/运营侧认为规则不统一易混淆，可退回"全模式锁定"，改动仅是一处条件判断，不影响架构。

### 6.5 本地存储的公平性边界（备忘，非首版实现项）

本地存储意味着玩家可改 localStorage 伪造灵敏度——但灵敏度本身只影响自己手感、不上报服务器、不改变弹道判定，**无作弊收益**。排位公平性争议若出现，评估方向是"档位同步上报"而非"服务器存档"，记录于此备查。

## 7. 边界与异常

### 7.1 无传感器设备 / 桌面端

- 检测规则见 §2.3。整组隐藏；若 localStorage 中残留非 0 档位（如换设备登录同账号导入），运行时**静默按关闭处理**，不弹 toast、不回写存储。
- 陀螺仪模块对"无传感器"必须是**零开销旁路**：不注册事件监听、不进主循环消费分支。

### 7.2 Toy webview 权限策略异常

| 异常 | 处理 |
| --- | --- |
| `requestPermission` 函数存在但调用抛错 / 返回非标准值 | 按 denied 走 §3.2，toast「当前环境不支持陀螺仪，已关闭。」 |
| 已授权但 `deviceorientation` 持续无有效数据（1.5s 内全 null） | 静默按挂起处理；设置页档位保持用户所选（不回写），下次进入自动重试检测。**不弹 toast**（无操作意义的报错不打扰） |
| webview 不派发 `deviceorientation`（部分安卓内核裁剪） | 同上：无数据 = 无效 = 挂起，设置组下次冷启动时按 §2.3 规则隐藏 |

### 7.3 数据漂移：**★ 首版结论 = 不做校准 / 重置中心**

- 架构依据：采用**增量式模型**（每事件对上一事件差分，累加到视角），不使用绝对姿态角。漂移的本质是绝对角缓慢偏离真值，增量式天然免疫稳态漂移——静止时差分≈0，不积累。
- 残余风险：部分机型融合磁力计的 absolute orientation 在磁干扰下有缓慢 bias，表现为"静止不动时极缓慢偏移"。该量级（约 <0.5°/min）在单局 3–5 分钟内不可感。
- **不做**"陀螺仪校准"按钮、"重置中心"手势。若上线后实测出现可感 bias，方案是"对局开始时以当帧姿态为基准重置差分参考"，一个变量赋值即可，预留。

### 7.4 平板横竖屏切换

- 游戏强制横屏；竖屏态本身不可玩，此时陀螺仪挂起。
- 横↔竖切换瞬间（含系统强制旋转弹窗）：**300ms 内丢弃全部 `deviceorientation` 事件**，防止旋转瞬间 yaw/pitch 轴定义突变产生一次大增量甩视角。恢复后重置差分参考（以恢复后第一个有效事件为基准，该事件本身丢弃）。

### 7.5 蓝牙手柄同时使用：**结论 = 逐帧仲裁，手柄 > 触屏 > 陀螺仪**

- 同一帧内若视角已收到**手柄摇杆**或**触屏滑动**的输入，该帧丢弃陀螺仪 pending 增量（不是加权混合）。
- 实现路径天然廉价：陀螺仪走 H2 同一视角入口，入口处按优先级短路即可。
- 不做"手柄连接时全局禁用陀螺仪"的粗粒度开关——插着手柄但仍用触屏开枪的混合操作是真实场景，逐帧仲裁不误伤。
- 手柄侧若有陀螺仪（如部分手柄自带体感）：**首版一律不读**，只处理手机本体传感器。

### 7.6 单帧增量钳制（异常防护）

- 单个 rAF 消费周期内，各轴应用增量钳制 **|Δ| ≤ 30°**。防护场景：设备被甩动/磕碰、传感器瞬时毛刺、后台恢复残留大值。超出部分直接截断，不累积。

## 8. 验收标准（共 14 条，可直接转用例）

**功能主路径**

1. 移动端设置页可见「陀螺仪」分组，含三档分段按钮 + 双滑条；默认档高亮「开镜开启」，双滑条默认 100%。
2. 档位=「总是开启」时，未开镜状态下转动手机，视角 yaw/pitch 随之变化，方向正确（右转手机=视角右转，上抬=视角上抬）。
3. 档位=「开镜开启」时，未开镜转动手机视角不动；开镜后转动生效；收镜立即停止（收镜前后视角无跳变、无回弹）。
4. 基础灵敏度与开镜灵敏度独立生效：基础 100%/开镜 200% 时，同一角速度下开镜视角速度约为未开镜的 2 倍（±10% 容差）。
5. 桌面端（或无传感器设备）设置页不显示陀螺仪整组；游戏功能无任何陀螺仪相关报错。

**权限（iOS 13+ / 支持 requestPermission 的环境）**

6. 首次选「开镜开启」/「总是开启」：权限弹窗在点击后立即出现；授权后档位生效并写入存储；冷启动后档位保持。
7. 权限拒绝后：档位自动回退为「关闭」，出现对应 toast 文案（与 §3.3 完全一致）；再次进入设置页档位显示为关闭。
8. 权限请求只发生在用户点选非关闭档的当次回调内；页面加载、恢复默认操作均不触发权限弹窗。

**状态机与鲁棒性**

9. 对局暂停/切后台期间陀螺仪不生效；切回前台恢复后前 2 个传感器事件被丢弃，视角无瞬移。
10. 死亡/观战期间转动手机视角不受陀螺仪影响；复活后自动恢复（2V2）。
11. 甩动手机（单帧大角度）后视角不出现 >30° 的瞬时跳变（钳制生效）。
12. 连接蓝牙手柄并推动视角摇杆的帧内，陀螺仪增量不叠加；松开摇杆后陀螺仪恢复生效。
13. 对战类对局进行中陀螺仪设置组置灰锁定；靶场中可实时调整并即时生效；退出对局后新值保持。
14. 连续游玩 10 分钟（乱斗单局+结算往返），无因陀螺仪模块导致的帧率下降（对照关闭档位基线，平均帧时长增量 <1ms）；`deviceorientation` 回调内无 DOM/渲染侧操作（代码走查确认）。
