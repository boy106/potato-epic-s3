## 一、5 个嫌疑点静态诊断结论

### S1 陀螺仪轴向符号 —— **最高嫌疑，判定：pitch 手性符号待真机确认（中置信度）；yaw 反向可能性低**

**现状实现**（gyro.js:424-436）：W3C 姿态四元数差分，世界系相对旋转投影分解：
- `dy = axisDeg(d, [0,0,1])` —— 绕**世界竖直轴**的带符号转角 → yaw。
- `dp = axisDeg(d, quatRotate(q,[0,1,0]))` —— 绕**设备顶边轴**的转角 → pitch；`pitchSign` 按"设备右缘的世界 Z 分量 ≥0 取 +1"翻转（gyro.js:428-431），意图覆盖左右横握两种手性。
- `yawRight = -S.emaY`、`dPitch = -ap` 两处内联符号（W5b 报告 §6.1 声明的待确认点）。

**链路自洽性核查**：引擎约定 `forward = (-sin yaw, ·, -cos yaw)`（companion.js:1148、mobs2.js:546 等多处一致）→ yaw 减小 = 视角右转。右转手机 → 世界系 dy 为负 → `yawRight=-emaY` 为正 → `lookWrite` 内 `p.yaw -= dYaw` → yaw 减小 → 右转 ✓。且触屏滑动走同一 `lookWrite` 入口（touch.js:621）且 S1 赛季真机无方向反馈 → **yaw 符号链在数学上与触屏语义一致**。W3C α/β/γ 以设备自然方向为参考系、浏览器不补偿屏幕方向，但世界系差分对此天然免疫（mock 已验证）。

**真机可能表现**：
- yaw 反了（右转手机视角左转）→ 低置信度，若出现即 S1-yaw；
- **上下颠倒**（抬头手机视角向下/反之）→ 中置信度，若出现即 pitch 手性符号约定弄反，这正是 W5b 明确遗留的"真机横屏确认"项。附带缺陷：`S.q` 为 null（静默期/恢复可见首帧）时 `pitchSign=0`，该帧 pitch 增量被静默丢弃（gyro.js:428-432，有事件流时仅影响 1 帧，轻微）。

**定位置信度**：pitch 颠倒 = 中；yaw 反向 = 低-中。已交付缓解：设置页"陀螺仪左右/上下反转"开关（见 §二），用户照 §三自测即可一键分辨四象限（yaw 正/反 × pitch 正/反），无需改码。

### S2 陀螺仪"开镜开启"档联动 —— 判定：链路正确；异常表现为"无反应"而非"方向错"（中置信度）

**现状实现**：`adsActive` 唯一事实源 `XZ.aimAmount(player) > 0.01`（gyro.js:199-207）；已在 `mods/xzguns/bundle.js` 核实定义存在（`aimAmount = e => e && e.xz && e.xz.aimT || 0`）。档位 1 时未开镜 `evaluate` 返回 null → 挂起并清空 pending。

**真机可能表现**：选"开镜开启"后转手机无反应——两种非缺陷场景：① Toy 基础模式 XZ 未加载，开镜档永不激活（W5b 已声明）；② 用户以为"开启"即全程生效。收镜瞬间 `aimT` 越过 0.01 即停，80ms 衰减尾（tailK=0.6）掩盖跳变，mock 已验证无回弹。**定位置信度**：中（但性质是"感知不生效"，非方向错误）。

### S3 开镜（ADS）视角链路 —— 判定：无缺陷迹象（低置信度问题）

**现状实现**：陀螺仪不写 FOV（FOV 联动在 xzguns 侧，gyro.js 无涉及）；开/收镜灵敏度切换发生在帧消费处 `getSens(g, st.ads ? "ads":"base")/100`（gyro.js:423），只影响后续帧、缓冲不重算 → 切换瞬间无跳变。开镜下触屏滑动灵敏度映射不变（touch.js:620-621 公式与开镜无关，与 S1 赛季一致）。

**真机可能表现**：开镜后视角仍按基础灵敏度动（对应 S2-② aimAmount 恒 0）；或开镜灵敏度滑条被调到极端值误判为"异常"。**定位置信度**：低。

### S4 触屏视角写入口 `lookWrite()` 帧级仲裁 —— 判定：无边界缺陷迹象（低置信度）

**现状实现**（touch.js:34-40 + gyro.js:398-405）：写入记录 `_lookWriteAt/_lookWriteSrc`；陀螺仪消费前若"自上次消费以来有 touch 写入"则丢弃本帧 pending（touch > gyro，非混合）。两侧均用 `performance.now()`，触屏 pointermove 与 rAF 同在主线程，无真机时序竞态。

**真机可能表现**：滑动中陀螺仪短暂让位（设计行为）；滑动停止后 EMA 残留可能产出 ≤单帧的小增量，表现为"松手后视角再滑一小段"——幅度受 ±30° 钳制约束，属 EMA 设计代价而非缺陷。**定位置信度**：低。

### S5 横竖屏切换 —— 判定：挂起时序依赖 Stage 适配，可能有边界表现（低-中置信度）

**现状实现**：mobile.js Stage 竖屏（`rotatePortrait` 默认开）时 CSS `rotate(90deg)` 旋转画布并 `translateX`（mobile.js:39-57），`Renderer.prototype.resize` 按 `Stage.w()/h()` 取**旋转后**尺寸（mobile.js:111-129）；gyro 以 `ui.h > ui.w` 判竖屏挂起（gyro.js:328）+ `orientationchange` 后 300ms 静默（gyro.js:307-312）。

**真机可能表现**：
1. 竖屏持握 + "旋转画面"开启时，画布已是横尺寸 → `ui.h < ui.w` → 陀螺仪**不挂起**（意外激活）。物理映射仍正确（世界系差分与画面 CSS 旋转解耦：物理抬头=画面抬头），但用户可能把"竖屏也能转视角"当作异常；
2. 横↔竖切换瞬间：orientationchange → 300ms 静默挂起，Stage 200ms 后才 update → 静默窗口覆盖 resize 时序，切换后约 0.3s 视角不动属设计行为，若用户在静默期内甩机会感到"卡一下"；
3. 若真机上 resize 时序错位导致 `ui.h > ui.w` 误判，表现为横屏陀螺仪不生效——自测清单第 5 步可分辨。**定位置信度**：低-中。

**综合判定**：最高嫌疑 = **S1 pitch 手性符号**（W5b 遗留待真机项，与"用户刚测完陀螺仪"的时点吻合）；其次 S2 的"感知不生效"类反馈；yaw 反向概率最低但已纳入开关覆盖。

## 二、真机自测开关实现方式

设置页 → 触控 → 灵敏度 → **陀螺仪分组**内新增两行用户可触达开关（potato.js:2709-2722）：

- `陀螺仪左右反转：开/关`（翻转 yaw 符号，bit1）
- `陀螺仪上下反转：开/关`（翻转 pitch 符号，bit2）

实现要点：
- 存储为 `game.settings.gyroFlip` 位掩码（0-3），随现有 `potato-settings` 单对象序列化走 localStorage，与 gyroMode/gyroSens 同模式；`save()` 复用 `g.saveSettings()` 路径。
- 应用点即 W5b 报告指出的两处内联符号（gyro.js:429-432）：`yawRight = -S.emaY * (flip&1 ? -1 : 1)`、`pitchUp = S.emaP * pitchSign * (flip&2 ? -1 : 1)`，不改任何其他逻辑；衰减尾复用 `lastApplied`（已含翻转）。
- 新 API：`Gyro.getFlip(g)` / `Gyro.toggleFlip(g, bit)`；对局中锁定（`matchLocked` → toast 拒绝）+ 行级 disabled，与既有分组锁定一致；行 UI 走既有 label()/onClick + relabel 刷新机制，`enabled` 用普通行原生 disabled 支持（potato.js:2923）。
- 「恢复默认」将 `gyroFlip` 复位为 0。
- 等效的一键切符号方案（改 `GYRO_TUNING`）不再需要——开关已覆盖其全部诊断场景。

## 三、真机自测清单（一页纸，交用户照做）

前置：设置 → 触控 → 陀螺仪档位选**「总是开启」**，进靶场；两行反转开关均为**关**。

| # | 操作 | 预期表现 | 若异常说明什么 |
| --- | --- | --- | --- |
| 1 | 横屏持机，**原地向右转手机 90°** | 视角同步向**右**转 | 视角向左 → 勾选「陀螺仪左右反转」后复测，恢复正常即 yaw 符号问题（S1-yaw） |
| 2 | 同姿势，**屏幕顶边向上抬**（抬头动作） | 视角同步向**上**看 | 视角向下 → 勾选「陀螺仪上下反转」复测，恢复即 pitch 手性问题（S1-pitch，最高嫌疑） |
| 3 | **换另一只手横握**（左右横握各做一次第 2 步） | 两种握法抬头均为"向上看" | 只有一只手颠倒 → 属 pitch 手性判定边界，两行开关都无法同时纠正 → 记录握法与现象回报（代码需改 pitchSign 判定，非用户可解） |
| 4 | 档位改「开镜开启」：未开镜转手机 → 开镜转手机 → 收镜 | 未开镜**完全不动**；开镜随动；收镜**立即停**（无滑动回弹） | 开镜后也不动 → 看 #8；未开镜就动 → aimAmount 判定问题（S2）；收镜有回弹 → 衰减尾参数问题（S3） |
| 5 | 开镜态对比灵敏度：基础调 10%、开镜调 300%，开镜前后转手机 | 开镜后明显"更灵敏"（约 30 倍观感） | 开镜前后一样 → 开镜标志位没接通（S2/S3） |
| 6 | 灵敏度分别调到 10% 和 300% 各转一圈 | 10% 极迟钝、300% 一圈约 30° 封顶（甩机钳制） | 300% 时视角瞬移超 30°/帧或 10% 仍猛 → 钳制/EMA 异常，回报现象 |
| 7 | 游戏中**横↔竖屏切换**各两次 | 切换后约 0.3 秒视角不动（静默期），随后恢复且方向不变 | 恢复后方向反了或永久不动 → 记录切换方向（横→竖/竖→横）回报（S5）；竖屏持握仍能转视角属已知表现（见报告 §一 S5-1），不算缺陷 |
| 8 | 切后台再回前台 2 秒后转手机 | 前 2 个事件被丢弃、无瞬移，随后正常 | 回前台视角瞬移 → 恢复丢弃逻辑异常（对照 gyro.js:244-248），回报 |
| 9 | 全部测完点「恢复默认」 | 两行反转开关回到「关」，灵敏度回 100% | 未复位 → 回报（resetDefaults 覆盖缺口） |

速判表：#1 反 + #2 反 = 两组都反（罕见，同时勾两个开关复测）；#1 反 = yaw 符号；#2 反 = pitch 符号（最可能）；#4/#5 异常 = 开镜联动；#7 异常 = 横竖屏适配。测完把勾选状态与现象回报即可精确定位。
