# POTATO EPIC 本地化现状盘点

## 1. 结论

当前是**中文硬编码的单语言客户端**，不是“已有 i18n、只缺翻译”的状态。`index.html` 为 `lang="zh-CN"`，未发现 locale/i18n/l10n/lang/translation 资源文件或统一字符串表；`mods/index.json` 的个别 `en` 字段只是英文名称，不构成多语言机制。

若首个目标是增加一种语言，改造量级评为 **L（接近 XL）**；在只有压缩 build、无源码的条件下，工程风险按 **XL** 管理。先恢复可维护源码/构建链，再抽取文案，不建议直接长期修改压缩 pack。

## 2. 静态扫描证据

扫描范围：102 个 pack 内模块、独立 HTML、mods 清单与 mod JS；重复打包的独立 `blockdata/worldgen_data/modapi` 不重复计数。

| 指标 | 结果 | 说明 |
|---|---:|---|
| 含中文的字符串字面量出现次数 | 约 6,556 | 自动扫描，含 UI、错误、提示、数据名、内部日志等 |
| 去重后的原始中文字面量 | 约 5,206 | 按原始引号字符串去重，尚未做语义合并 |
| 去重字面量中的汉字数 | 约 36,198 | 不含变量、HTML 可见文本和全部动态拼接上下文 |
| pack 内模块中文出现次数 | 5,482 | 覆盖 gameplay、UI、账号、联网、live ops 等 |
| 统一语言资源文件 | 0 | 未发现 |
| 当前可本地化抽取率 | 按统一字符串表口径为 0% | 不代表所有文案均已人工盘点 |

主要集中区域：`blockdata`（1,048 次）、`itemdata`（519）、`potato`（490）、`screens`（446）、`net`（289）、`blocks`（286）、`account`（215）；此外 `xzguns/bundle.js` 有 706 次、`xzrange/code.js` 有 311 次。它们不仅是菜单翻译，还包括物品/方块数据、战斗反馈、错误处理、活动与社区文本。

扫描限制：正则统计不等于完整 AST 抽取；HTML 标签文本、拼接结果、后端 news/live 下发文案、图片内文字与音频需另审。因此 5,206 是工作量基线，不是最终翻译条目承诺。

## 3. 覆盖率盘点

| 层级 | 当前状态 | 多语言缺口 |
|---|---|---|
| 启动页/基础 HTML | 中文与英文混排，`zh-CN` 固定 | 可见文本、加载提示、操作提示硬编码 |
| 核心 UI/屏幕 | 大量中文字符串直接写入模块 | 无消息 key、语言回退、复数/性别规则 |
| 物品/方块/实体数据 | 中文名称和描述嵌入数据 | 显示名与内部 ID 未分离 |
| 战斗与 mod | 武器、配件、教程、反馈中文硬编码 | 动态插值、语序、术语一致性需处理 |
| 联网/账号/云存档 | 中文错误和状态提示硬编码 | 后端错误映射与客户端翻译边界未定义 |
| Live Ops | news/checkin/shareholders/live 含中文 | 后端下发内容也需 locale 字段和默认语言 |
| 美术/音频 | 未见语言资源目录 | 图内文字、字幕、VO 是否需本地化未盘清 |
| 排版 | Canvas 自绘 UI、fitText/Font.width 等 | 长文本、换行、字体、RTL、截断需专项验收 |

中文当前版本可继续以单语言发布，但不得宣称已具备多语言能力；多语言支持不应作为当前中文热修的隐式范围。

## 4. 目标架构

1. **稳定内部 ID**：物品、武器、mod、活动使用不变 ID，显示名进入字符串表，禁止拿中文当逻辑键。
2. **消息 API**：如 `t('weapon.reload', { weapon })`；支持参数、复数、转义、缺失 key 回退 zh-CN 并上报。
3. **资源布局**：`locales/zh-CN/*.json` 为源语言基线，其他语言同 key；带 `schema_version`，按功能拆分并可延迟加载。
4. **上下文元数据**：每个 key 记录模块、用途、截图、变量说明、最大长度；禁止译员翻译变量和内部 ID。
5. **Canvas 排版**：按真实字体测量，支持自动换行、扩展空间和截断提示；预留约 30–50% 文本膨胀。
6. **后端协同**：news/live/checkin 等使用 locale 请求和本地化内容，服务端错误返回稳定 code，由客户端翻译。
7. **语言设置**：默认 `zh-CN`，用户选择持久化；语言回退顺序明确，切换不应清存档或重置活动状态。
8. **冻结流程**：候选字符串冻结 → 翻译 → 语境/文化审查 → 伪本地化与版式 QA → 发布；冻结后仅 hotfix 可改字符串。

RTL 只有确定支持阿拉伯语等语言时才进入首期范围，但消息 API 不应假设所有语言语序与中文相同。

## 5. 改造量级评估（首个新增语言）

前提：先恢复源码和可重复构建；一个新增语种；含核心客户端、内置两个 mod、后端在线文案和 QA。

| 工作包 | 估算 |
|---|---:|
| 源码/构建恢复、AST 扫描与文案归属清理 | 1–2 人周；无源码另增风险缓冲 |
| i18n runtime、字符串表、抽取约 5,206 条、参数化 | 4–6 人周 |
| Canvas/触控 UI、字体、长文本、动态内容适配 | 2–4 人周 |
| 翻译、术语表、语境与文化审校（每语种） | 2–4 人周，可并行 |
| 功能、伪本地化、版式、后端与回归 QA | 2–4 人周 |
| **合计** | **约 10–18 人周，2–3 人并行约 8–12 日历周** |

若始终只有压缩 build，需要额外 2–4 人周并保留高回归风险，总量可能超过 20 人周。后续已有管线的新增语种主要是翻译、审校和 QA，不应重复首期全部工程成本。

## 6. 分阶段建议

- **P0（现在，1 次迭代内）**：保存本次扫描基线；新增文案先登记 key/来源；禁止继续新增无必要的中文逻辑键。
- **P1（源码恢复后）**：选择 `potato` 高频 UI + 启动页做垂直切片，验证 Canvas、mod、live/news 和回退链路。
- **P2**：批量抽取核心与 mod，建立译员简报、术语表、伪本地化和截图审查。
- **P3**：首个语种完整 QA 后再扩展；每版生成缺失/过期 key 覆盖率报告。

## 7. 本地化发布门

- 源语言与目标语言 key 覆盖率 100%，无未解释缺失；变量与 HTML 转义正确。
- 术语、文化/敏感性、平台表述、活动日期与奖励经审校。
- 伪本地化、长文本、窄屏、横竖屏、Canvas 字体与输入法通过。
- 后端下发与客户端回退验证；缺翻译时不白屏、不阻断对局。
- 字符串冻结后改动必须重新触发翻译与相关 QA。
