# 01 · 天梯、段位与赛季（现状版 GDD）

> 出处代号见 `numbers.md`。核心实现位于 `mods/xzguns/bundle.js`（`XZ.ladder` 模块）与 `js/pack4.js` 的 `potato.js` / `account.js` / `telemetry.js`。**天梯分的最终记账在服务端**（/api/ladder/*），客户端 `delta()` 函数与文案是同一套规则的权威描述。

## 1. 概述

Elo 制天梯：7 个段位，起始 100 分（石头段），1V1/2V2/淘汰赛共用一套分数；人机对战在 800 分以下按难度折算胜场加分；乱斗不计分。第一赛季进行中，重置规则在服务端，客户端无实现痕迹。

## 2. 玩家价值

- 快速可感的段位反馈：每 200~150 分一个段位，12 格进度条（排位页）+ 10 格（大厅）双可视化。
- 「赢强者多加，输弱者多扣」的 Elo 公平感文案直接写在 UI 上。
- 输了不打压：人机输了不扣分、排位输有降级保护（对等/更强对手时）。

### 3.2 天梯分公式 `delta(我分, 对手分, 我胜局, 对手胜局, opts)`（N-04~09）

```
期望胜率 E = 1 / (1 + 10^((对手分 - 我分)/300))      // Elo，除数 300（非标准 400）
表现系数 f = 2 × (0.5 - E)

胜: +max(1, GAIN[段位] × (1 + 0.15×(净胜局数-1)) × (1 + 0.6×f))
负: -max(1, LOSS[段位] × (1 + 0.15×(净负局数-1)) × (1 - 0.6×f))
平: ±0.3 × GAIN[段位] × f                            // Bo5 打满局内基本不出现

段位增益 GAIN = [40, 30, 22, 16, 12, 8, 3]           // 原木→土豆之神
段位减损 LOSS = [4, 10, 12, 13, 12, 11, 6]
```

- **局差放大**：净胜 2 局 ×(1+0.15)，净胜 3 局 ×(1+0.30)，以此类推；败方对称。
- **重复对手抑制**（N-08）：与同一对手第 2~3 场 → 分数 ×0.5；第 4 场起 → 0。抑制计数来源（客户端传 repeat）未在客户端完整可见，中置信。
- **定级赛放大**（N-09）：`opts.placement` → 分数 ×1.5。客户端无调用点，推断为服务端新号定级用，中置信。
- **降级保护**（N-10）：输分导致跨段位下降、且**对手段位 ≥ 我段位**时，分数落回当前段位下限（不掉段）。语义：输给同段/更强不掉段，输给弱者才可能掉段。设计意图存疑 → OQ-1。
- 分数下限 0；四舍五入取整。

### 3.3 人机加分（N-12~14）

- UI 明文：`人机对战赢了也加天梯分：简单 ×10% · 普通 ×25% · 困难 ×50%（800 分以下 · 乱斗除外）`。
- 结算文案：`排位胜场 +X 的 Y%`——服务端先按 Elo 算「若为排位胜场」的得分，再乘难度系数（easy10/normal25/hard50）。
- 条件：**只有 <800 分才加**；输了不扣分；淘汰赛每赢一场都算；乱斗从不加分。
- 结算成功展示：段位图标 + 当前分 + 增量 + 「人机{难度} · 排位胜场 +full 的 pct%」。

### 3.4 排位资格门（N-15）

- 未登录不能排位；`rankLocked()` → 弹解锁页：「关注 UP 主就能排位，还能解锁薯核 CORE 全部 8 把枪和所有刀」。
- 门模式由服务端下发（`gate: off/follow/triple`），`follow` 时只需关注，`triple` 需关注+三连。

### 3.5 结算与仲裁（N-16~18）

- 双人对局双方各自上报结果；**对方离开 20 秒后自动算分，最多等 3 分钟**（pending）。
- 双方结果对不上（disputed）→ 这场不计分。
- 房主网络不稳定导致中断（void）→ 不计分。
- 反作弊（N-19）：检测到段位分异常增长 → 分数清零 + 1 小时禁止联机。

### 3.6 模式细则（复述自 00 模式矩阵，与计分相关部分）

- 1V1：同段位优先；Bo5 打满五局；每局固定枪。
- 2V2：好友组队或随机；队友无伤害；一方全倒该局结束；Bo5 打满。
- 淘汰赛：8 人单败；每场 Bo5、每局随机枪；同轮出局按伤害排名；每赢一场都计胜场。

## 5. 边界与异常

| 异常 | 现状处理 |
|---|---|
| 对手掉线 | 上报等待 20s → 自动判分，上限 3 分钟 |
| 双方结果冲突 | disputed，不计分 |
| 房主断线 | void，不计分 |
| 分数异常暴涨 | 清零 + 1h 联机封禁 |
| 未登录点排位 | 弹登录页 |
| 关注门未满足 | 弹解锁引导页（含免费解锁内容清单） |
| 反复刷同一对手 | ×0.5 / ×0 抑制 |
| 打满 5 局 2:2 后 | 无平局分支可达（w+l=5）；平局分支为自定义局数（3 局=2 胜、7 局=4 胜）预留 |

## 6. 与其他系统耦合

- **经济**：排位时长 → 土豆币 15/min（上限 12 分钟/场）；每日首胜奖励。
- **解锁**：段位达成 → 「晋升」系列 AR 皮肤（rank0~6 对应 7 个段位）。
- **社交**：匹配同段位优先；排行榜 Top10 展示（空榜文案「还没有人打完一场天梯 · 来做第一个」）。
- **反作弊/遥测**：telemetry.js 上报对局行为。

## 7. 现状证据

- `bundle.js` `XZ.ladder`：TIERS 表、delta() 全公式、START=100、tierName（#名次）。
- `potato.js`：人机面板文案（Et={easy:10,normal:25,hard:50}、Ct=800）、排位页文案、结算文案（pending/disputed/void/banned/bonus）。
- 结算里还有 `表现加分 bonus（评分 rt.score）`——排位场有基于评分的额外加分，服务端计算，**公式未在客户端出现**（N-20，低置信细节）。
- API：`/api/ladder/me`、`/api/ladder/top`；游客身份走 pm 服务器 `/guest`。
