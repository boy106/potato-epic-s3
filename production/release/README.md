## 当前事实与证据边界

审计对象：`2026.11.14a` 离线 build。

- 127 个文件，8,285,516 字节；四个 pack 解出 102 个模块。
- 两个内置 mod 共登记 116 个文件，均存在且无未登记文件。
- `GAME_BUILD=2026.11.14a`，启动页却显示 `BUILD 2026.11`。
- `pack4.js` 内模块动态请求 `js/skins_data.js`，包内缺失；错误会回退为空预设，可能掩盖漏打包。
- `xzguns.size` / `xzrange.size` 与实际文件总字节数不一致，需明确字段口径并重生清单。
- index 与 integrity 存在 `force-cache`；mod 清单/下载使用 `no-cache`；未发现 Service Worker。
- 后端与遥测路径已从代码确认，但本轮未执行完整 Toy 容器、rooms/pm 业务、云存档或回落实切演练。
- 无 git 历史可生成可信变更日志；补丁说明只能以已确认变更和 QA 证据为源，不能从模块名臆造更新条目。

## 标准发布流

```text
冻结候选与范围
  → 分配 BUILD / 更新单源展示
  → 全量文件清单 + mod/动态资源核验
  → QA + 后端 + Toy 容器 + telemetry/integrity
  → 44 项 checklist / go-no-go 人工签字
  → 不可变归档与回滚演练确认
  → 原子发布 + 缓存失效
  → 双会话验证 + 观察窗口
  → 玩家公告 + 审计归档
```

## G2 自评

### 本次发布工程交付：**CONCERNS**

六份指定文档已齐套，规范、44 项清单、热修回滚、本地化量化与风险均可审查；但仍有无源码/CI、平台原子发布能力未证实、回滚未演练和在线服务未实测等过程缺口，不能自评 PASS。

| G2 维度 | 自评 | 理由 |
|---|---|---|
| 版本规范与可追溯 | CONCERNS | 规范完整；当前包展示版本仍不一致，且尚无自动单源生成 |
| 静态资源发布门 | CONCERNS | 检查覆盖 HTML、动态脚本、worker、mod 与音频；当前实测仍有 FAIL 项 |
| 补丁沟通 | PASS | 模板含四分区、数据说明和基于当前特征的明确示例 |
| 热修与回滚 | CONCERNS | 步骤、缓存和审计完整；原子切换能力及演练尚无实证 |
| 后端/遥测门控 | CONCERNS | 已列真实路径与验证口径；未伪造连通或上报通过结论 |
| 本地化盘点 | PASS（盘点交付） | 有覆盖率、分布、扫描边界、架构与人周估算；产品本身未多语言化 |

### 当前 build 的直接放行判定：**NO-GO**

阻断项不是文档缺失，而是已观察到的候选问题：展示版本不一致、`skins_data.js` 缺失、两个 mod `size` 与实际字节不符。修复后必须重跑对应检查；任何 Blocker 未清均不放行，除非用户明确豁免且不涉及数据/安全风险。

## 下一步优先级

1. **P0**：补齐或移除 `skins_data.js` 依赖；重生 mod 清单；统一完整版本展示。
2. **P0**：把当前包与上一稳定包做不可变归档、完整 SHA-256 和一次真实回滚演练。
3. **P0**：确认 B站 Toy 原子发布/缓存刷新能力，以新旧两种会话验证无混包。
4. **P0**：由 QA/代码/后端补齐 Toy 容器、rooms/pm、cloudsave、telemetry 与 integrity 实测证据。
5. **P1**：恢复源码和版本管理，生成候选差异、文件清单与版本号的自动检查，再推进首个 i18n 垂直切片。
