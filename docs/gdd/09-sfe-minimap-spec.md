## 1. 目标与非目标

- **目标**：① 玩家在 10~15 分钟局内随时掌握自身方位、POI 分布、撤离点开放状态，降低"迷路找不到撤离点"的负反馈；② 威胁情报以"稀缺、有时效"的方式呈现，**服务而非消解**紧张与贪婪的核心体验（06 号文档 §1.3 美学 A）。
- **非目标**：不做路标编辑（WaypointScreen 不进 SFE，局内世界即抛无持久路标需求）；不做旋转地图（ north-up 固定朝向，自身箭头旋转，实现最简、读图一致性最好）；不做小地图点击寻路/传送。

### 2.2 按住展开大图（增强现有交互）

- **交互不变**：全图按钮按住 / `M` 键按住（F3 现有接线），松开即关，不阻塞移动与开火输入。
- **增强点**：
  1. **底图升级**：`drawFullMap` 的纯色底替换为 §3 预渲染底图的 **0.5× 全览**（720² → 360px 见方，居中显示），地形/地貌一眼可读（现状纯色底无法分辨水陆与聚落）。
  2. **缩放档位**：0.5×（全览 360px）/ 1×（1px=1 方块，跟随手指/鼠标拖动平移）两档，点击图面或双指捏合切换；默认 0.5×。

## 3. 底图方案：720² 大图预渲染低分辨率底图

### 3.1 基本参数

| 参数 | 值 | 依据 |
| --- | --- | --- |
| 底图分辨率 | **360×360 px**（每 2×2 方块采样 1 像素，取 2×2 内 `surfaceY` 顶块 `mapColorOf` 调色） | 设计·中：小窗 64px 视窗只需 1px=1 方块，底图 360² 足够 1× 档双线性拉伸不糊；720² 原分辨率底图内存翻倍且无读图收益 |
| 渲染数据源 | 对局 seed 的 `heightAt`/地表块调色（与 F1 同一套 `MAP_PAL` 调色板，水/高差明暗梯度沿用） | 引用·高 |
| 渲染时机 | **进图 DEPLOY 段（30s）后台分帧渲染**：按 chunk 行带推进，每帧预算 ≤4ms（实测校准），45×45=2025 chunk、每帧 4 chunk ≈ 506 帧 ≈ **8~17s 完成**，最迟 DEPLOY 结束前不可用时按已渲染区域显示 | 设计·中 |
| 渲染线程 | 主线程分帧（Canvas 2D putImageData），**不进 gen_worker**（worker 内无调色板与渲染上下文，且 8~17s 的一次性成本可接受） | 设计·中 |

### 3.2 缓存策略

| 层 | 策略 |
| --- | --- |
| 对局内 | 一局一渲染：底图离屏 Canvas（360²）+ 源 ImageData 各持一份，整局复用；**不逐帧重采样**（这是与 F1 每 500ms 重扫描的本质区别，也是 720² 大图上唯一可持续的方案） |
| 局内更新 | 挖/放方块以 **chunk 为脏粒度**标记，每帧最多重绘 2 个脏 chunk 对应的底图矩形（局部 putImageData），脏区 2s 内可见 |
| 跨局 | **不缓存**：对局制一局一结、固定 seed 同图，理论可跨局复用，但底图仅 0.5MB 且渲染在 DEPLOY 段无感完成，缓存换来的复杂度（存档体积、地图版本失效判断 `mapVersion`）不划算；localStorage/IndexedDB 不落盘 |
| 释放 | 结算页进入时整体置 null，随对局释放 |

### 3.3 内存预算

| 项 | 占用 |
| --- | --- |
| 底图 ImageData（360² RGBA） | ≈0.5 MB |
| 底图离屏 Canvas（360²） | ≈0.5 MB（GPU 侧纹理按实现计，同量级） |
| 小窗视窗复用底图 drawImage 裁剪 | 0（无独立缓冲） |
| **合计** | **≤1.5 MB**，含 markup 余量按 **≤2 MB** 验收（对照：06 号文档 §6.5 大地图内存增量 60~110MB，小地图占比 <2%） |

### 4.2 威胁信息：两方案对比与推荐

| | **方案 A：常驻威胁层** | **方案 B：情报扫描机制（推荐）** |
| --- | --- | --- |
| 形态 | 小窗直接画 24 只激活 AI 红点（实时）+ 枪声脉冲 | 枪声脉冲（被动）+ 主动扫描（按需）：扫描后短暂显示 AI 快照脉冲 |

| 玩法影响 | **挂机雷达**：AI 索敌半径 24 格 < 小窗 64 格视野，玩家可全程贴边绕行，遭遇战系统被掏空（F6）；"贪心决策"退化成"看图避战" | 情报成为**稀缺资源**：扫不扫、什么时候扫、扫完趁脉冲窗口进不进主 POI，本身是贪心决策的一环；遭遇战的突然性保留 |
| 紧张感 | 与 06 号文档 §1.3 美学支柱（紧张与贪婪）直接冲突 | 一致：信息不完全、有时效，代价（冷却期裸奔）真实 |
| 性能 | 两者绘制成本相同（≤24 点 + 少量脉冲环），不构成取舍依据 | 同左 |

| 冷却 UI | 扫描按钮常显冷却环；DEPLOY 段首次落地给一次免费教学扫描 | 设计·中 |

## 5. 性能约束

| 项 | 预算 | 说明 |
| --- | --- | --- |
| 渲染 API | **Canvas 2D**（与 F5 现有 HUD 同栈）：底图 `drawImage` 裁剪 1 次/帧 + 标记矢量绘制 | 不引入 WebGL overlay——现有 HUD/ui.ctx 全是 2D，单层小窗无 WebGL 必要；红线"不引入新文件类型/新渲染管线" |
| 每帧绘制预算 | 小窗态 ≤**16 次 draw call**、≤**0.5ms**；大图展开态 ≤**40 次 draw call**、≤**1.5ms**；底图分帧渲染期间额外 ≤4ms（仅 DEPLOY 段，见 §3.1） | 设计·中：标记总量有硬上限（主 POI ≤8、散点 ≤15、撤离点 ≤4、AI 脉冲 ≤24、枪声环 ≤8 同屏） |
| 更新节流 | 标记层位置重投影每帧执行（纯算术，便宜）；**底图不逐帧更新**（仅脏 chunk，§3.2） | 引用·高（沿用 F1 500ms 节流思路并加强为"只更标记不更底图"） |
| 缩放档位 | 小窗固定 1px=1 方块；大图 0.5× / 1× 两档（§2.2） | 设计·中 |
| 降档 | 低端机（06 号文档 §8.3 设备分档）小窗尺寸 64→48px、底图分辨率 360²→240²、扫描快照 5s→4s；不影响信息构成 | 设计·低 |
| 最低端目标 | 对局全程（含大图按住）≥30fps（06 号文档 §6.5 基线不变） | 引用·高 |

## 7. 验收标准（共 7 条）

1. **常驻小窗**：搜打撤对局中右上角出现 64×64 小窗（设置可关），显示地形底图、主 POI 金点、散点灰点、撤离点三态色标、白色朝向箭头随视角旋转；`self.POTATO` 环境下照常可用（不受沙盒 Minimap 平台禁用影响，开关独立）。
2. **底图预渲染**：进图后 DEPLOY 段（≤30s）完成 720² → 360² 底图渲染，期间未渲染区显示暗色蒙层不黑块；完成后小窗/大图在全图任意位置均有地形读数；常驻内存 ≤2MB，结算后全部释放。
3. **局内更新**：挖/放方块所在 chunk 的底图区域在 ≤2s 内反映到小窗与大图。
4. **大图交互**：按住按钮或 `M` 键弹出大图（0.5× 全览默认档，1× 可拖动），松开即关；期间移动/开火不受阻塞；撤离点名称与开放态标注正确（对照 06 号文档 §9.6 时间轴）。
5. **威胁方案 B**：常驻小窗与大图在任何时刻**不直接显示 AI 实时位置**；主动扫描（按钮/N 键）受 45s 冷却，扫描后 48 格内 AI 快照脉冲显示 5s 后消失；AI 开火产生 2s 声源脉冲环；全部参数在调参块可调。
6. **帧预算**：中端机实测小窗态 HUD 绘制 ≤0.5ms/帧、大图态 ≤1.5ms/帧；最低端目标设备（降档参数）对局全程含按住大图 ≥30fps。
7. **数值集中**：本规格全部新增数值（底图分辨率/分帧预算/扫描半径/时长/冷却/降档参数等）集中于调参常量块，无散落硬编码（代码走查确认）。
